# 人工看台数据约定 v0：L1 标签与原生事实

> Solo-Flow 文档版本：**v3.1**

本文件固化 Human 已确认的 L1 接入约定，不修改 Solo-Flow 的 WORKFLOW、执行顺序或合并授权。
依据：[立项 R02](https://github.com/zwmhua/HoSaiLei/pull/36#issuecomment-6612841655)、[Human 确认与实施范围](https://github.com/zwmhua/HoSaiLei/pull/36#issuecomment-6622200364)。
原设计：[L1 功能设计 R02](https://github.com/zwmhua/HoSaiLei/pull/36#issuecomment-6612540622)，SHA-256：
`8842359d41ae72ccbfb67d92d1e1990fcc1bf836bf703f023bcfe58e779f8404`。
本轮增量优先：L1 自定义业务字段只读标签；卡号、请求与阻断等正文结构化解析整体留 L1.1。
规范以 Human 最终批准并合并的版本为准；文档落地不表示已创建真实标签、迁移历史数据或接通产品。

## 1. 适用对象与身份

接入配置明确完整仓库名及哪些 Issue/PR 已采用 v0、哪些是未迁移历史，不含秘密。
已接入对象缺字段、值非法、多个值冲突分别显示具体缺项/错误/冲突；历史无约定字段才显示待确认。
内部实体以 GitHub 稳定 repository ID、对象种类及编号标识；展示完整 owner/repo 与准确来源链接。
同号跨仓库、Issue 与 PR 独立；卡数、PR数、待办数、阻断数按各自身份去重，不混用计数口径。
只有原生明确归属才能计入已确认卡关系；普通 PR 保留入口，没有关系时不虚构卡号。

## 2. 精确标签字典

| 字段 | 精确标签名 | 基数与读取 |
| --- | --- | --- |
| 业务阶段 | `stage:发卡`、`stage:开发`、`stage:验收`、`stage:QA`、`stage:等你`、`stage:已合并` | 每个接入 Issue/PR 恰好1个，分别读取 |
| Human 待办 | `human:待批准`、`human:待签字`、`human:待合并` | 0～3种可并存，每种分别计数 |
| 当前负责人 | `bot:阿卡`、`bot:阿C`、`bot:阿bob`、`bot:阿Pi`、`bot:QA-deepseek` | 每个已派发对象恰好1个，交接替换 |

前缀、半角冒号、大小写与名称精确匹配；同前缀其他值显示未登记标签，不模糊映射，颜色不参与逻辑。
缺 stage/bot 必填项分别提示；同一字段多个值提示冲突，不凭作者或其他对象选一个值。
没有 human 标签表示没有被标注的当前 Human 待办，不属于必填项缺失。
stage:等你 不代替具体 human 类型；有效 human 待办不因阶段不是“等你”而隐藏。
阶段与 PR 原生 Draft/open/closed/merged 分开；标签与原生状态不一致时保留双方事实并提示，不补写标签。
PR 不继承 Issue 的阶段或负责人，不按作者、assignee、最近评论者推断 bot。
负责人标签不证明 bot 正在运行、空闲或可调用；无已约定运行接口时运行状态为 UNKNOWN。

## 3. Human 待办、轮次与行动

待办身份由仓库/对象、human 类型及本轮标签加入事件组成；同一对象多类型分别计数、计时。
等待起点只取本轮标签加入事件的源时间；不得用 PR 创建、评论、首次发现或本地刷新时间代替。
移除后重加构成新一轮；缺事件起点时保留待办类型并显示缺少等待起点，不伪造时长。
按等待时长最长优先展示；STALE 时冻结到对应快照，不把陈旧事实延长成新实时证据。
发起方保留请求原因、对象/范围及必要候选的原文入口；L1 不自动解析正文结构化行。
未定位原因/范围时显示“原因见原文/未定位”，不能声称原文没有原因或伪造提取结果。
Issue 待办没有明确目标 PR 时显示“待关联PR”，只给该 Issue 入口，不随意挑第一个关联 PR。
仅移除 human 标签不证明已处理；没有完成、撤回等证据时保留处置待核实。
实际 merged 可结束待合并动作，但不补造 Human 授权；closed 不等于 merged，旧候选决定不套新 head。
行动按钮只打开准确 PR/Issue/评论来源；点击跳转不表示批准、签字、请求处置或合并已经发生。
共用账号名、OWNER、bot 同意/引用、标签和 CI 绿都不单独证明 Human 本人身份及授权范围。
身份或范围无法核实时保留原文与待核实；L3 开放任何写入前另行解决 Human 身份及范围核验。

## 4. 卡—PR 关系与阻断

只采用 GitHub 明确记录的 PR 关闭 Issue 关联/明确连接，不按标题、作者、数字或正文卡号猜关系。
一卡多 PR、多卡共 PR 保留每条明确关系及来源；一个 PR merged 不代表整张卡完成。
普通 cross-reference 仅为相关引用，不升格为所属卡或依赖；不新增 card:*、blocked:* 标签补关系。
关系未建立或不可读时显示未关联卡/关联待核实，保留准确入口，不用正文卡号作为备用判定源。
可用固定只读 `gh pr view --json closingIssuesReferences` 查询原生关闭关联；查询可调用不等于产品已接通。
依赖仅取 GitHub 原生明确 blocked-by 关系及被依赖对象的实际状态；普通 open Issue 链接不是阻断依据。
依赖接口不可用、403或分页不完整时为 UNKNOWN，不能按空结果解除旧阻断。
当前 head CI 失败可作已知阻断；未满足的原生明确依赖与信息缺口分列，同源去重保留影响对象。
没有已批准标签或原生结构依据的正文阻断只展示原文并标信息待核实，不作语义识别。

## 5. CI、历史与来源元信息

CI 只展示当前 PR head 对应的 check runs 与 commit statuses，保留检查标识、最新尝试、原值及来源。
读取 head、查询该 SHA 检查、重读 head；一次变化即 UNKNOWN，下一轮普通刷新再读。
旧成功仅作历史，不覆盖当前失败；未确认 required checks 范围时只说当前已读取检查，不说全部门禁通过。
成功绿、失败红、中性未知灰；原生 PR 状态、业务阶段与 CI 分别展示，不由 CI 推进阶段。
阶段历史取标签事件；最近评论取普通顶层会话评论，保留所属 Issue/PR、源标识、源时间与原文入口。
整卡详情保留全部确认关联 PR；历史/评论分页不完整与确无记录分别说明，不冒充完整审计。
事件没有独立可达地址时链接准确 Issue/PR，并说明来源类型，不编造深链。

## 6. 数据质量、快照与读取安全

统一脱敏 DTO 供待办、进度、阻断、详情和筛选复用；不在前后端分别猜业务状态。
按仓库/对象/数据区记录来源版本、源时间、最近尝试、上次成功、完整性及错误；失败不更新成功时间。
首次读取，前台60秒刷新、后台暂停，回前台超过60秒再读；同范围一轮在途，失效响应不覆盖当前候选。
分源超过3分钟或明确失败为 STALE；重启旧快照先 STALE，无快照为 UNKNOWN，不报告全局读取成功。
失败、缺页或部分读取不能删除未复验的关系、待办与阻断，也不因缺页把对象判成完成。
本地只保存脱敏归一化事实与必要来源元信息；位置为应用专用 `%LOCALAPPDATA%/Solo-Flow-Workbench/state`。
不存 token、请求头、完整原始 API 响应，不清理旧证据、用户数据或未知目录。
只读范围是配置仓库的身份、Issue/PR、标签/事件、原生关系/依赖、普通评论与当前 SHA 检查等明确端点。
后端固定参数读取 REST GET 与白名单 GraphQL 只读 query；禁止 mutation、任意 query/API路径或 shell。
GraphQL 查询的 HTTP POST 不等于业务写入；浏览器不能提交任意上游命令，凭据不导出到前端。
外部正文安全文本展示，危险链接拒绝；凭据不进入日志、缓存、localStorage、截图或导出。
看台没有评论、打标、改负责人、批准、签字、重跑CI、合并、部署或启动 Agent 的业务执行入口。

## 7. 数据生产与版本引用

由另获授权的维护者准备字典标签与采用范围；本PR只落文档，不创建或修改真实标签、权限或配置。
发卡方维护 Issue，执行者独立维护各 PR 的 stage/bot；责任方维护请求标签及事件来源，交接替换负责人。
L1 消费者始终只读，不为修复缺项而补写标签、负责人、关系或决定。
接入后核对正式来源是否足够；缺失时如实 UNKNOWN，不用展示功能冒充生产流程已经完成。
Workbench 在依赖契约的实现前，引用本文件最终合并 commit SHA 与规范文件 SHA-256（按 Git blob 原始字节），运行字典与测试锁定该版。
不以 PR 临时 merge SHA、待审草稿或前端另写的近似字典代替最终规范；升级规范另走明确审阅。

## 8. L1.1 与验收边界

L1.1 才处理 `卡号:`、请求类型/原因/目标PR/候选SHA、阻断/依赖/解除等正文结构化行。
对应生产模板、格式校验、正文回退解析与自动语义判断都不属于本轮 L1；正文和评论仍可安全阅读。
核心 AC01 按标签字典/缺项/错误/冲突验收，AC02 按原生明确关系验收，不沿用原设计正文卡号口径。
本文件不是产品实现或测试结果；后续各卡自带测试，最终 W15 在真实本地服务/页面与隔离假 GitHub 上逐项验证。
