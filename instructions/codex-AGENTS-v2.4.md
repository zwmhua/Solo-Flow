## 原则
默认简体中文。正确优先于速度，证据优先于声明，最小修改优先于重构。没实际运行过的，不写"通过"。

## 授权
- Human 派发 Issue（或快车道指令）授权白名单内开发、跑定向测试、本地提交。远端 PR 卡按卡面推送 `task/N`、提 PR 并汇总证据；获准的本地交付按 WORKFLOW §6 的本地通道。
- 以下必须 Human 对具体动作明确授权：合并、部署、rebase / 强推 / 改写历史 / revert、不可恢复删除、生产数据、凭据或权限变更、明显付费或大规模调用。
- 永远不改：`.github/workflows/`、`STATUS.md`、`docs/nodes/`。Issue 不能授权例外，只有 Human 明确授权才行。
- **卡内测试资源许可**：同一卡、同用途、同资源与权限范围、仍有效的明确授权，不仅因回修换 SHA 就作废；新 SHA 必须重跑适用检查，按影响范围复核并将正式 CI 和适用的独立验收结论重新绑定到新 SHA。啊bob 按卡面要求介入，QA 按标签要求静态复核。仅本次或仅旧 SHA 的授权不自动续期。资源许可延续不等于沿用旧 SHA 的验收结论。
- **许可边界**：新任务、扩大范围或权限、凭据变更、服务启停、真实下单、部署、破坏动作均不自动授权；已拒绝、撤销、过期或已耗尽的一次性许可不得复活。
- 平台自身强制审批照常，不可绕过；不默认读取秘密，不构成永久授权。

## 开工前（不符按 X1 报告）
1. 读 `ARCHITECTURE.md` 和 Issue；读不到就停止依赖它们的工作，不凭记忆猜。
2. `git status` 有未提交或未知改动时，保留现场，不清理不覆盖。按 WORKFLOW §3 划定 X1 的影响范围，目标工作树未确认干净时停止实施。获准且可安全隔离的只读检查可继续；只读许可不授权执行项目代码、修改文件、操作服务或产生远端写入。旧现场隔离沿用 WORKFLOW §3 的 v2.4.4 条款。
3. 从核准的最新 main HEAD 建 `task/N`；获准的本地通道采用更新后的本地 main。同名分支或 PR 已存在，先核对，不覆盖。
4. 白名单以 Issue 为准；快车道以 Human 指令为准。
5. AGENTS.md、ARCHITECTURE.md、Issue、现有代码互相对不上：停止受影响部分并报告，风险影响整体或无法划清边界时整卡停止。

## 实施
1. 先把 Issue 验收点写成测试，再写代码。不删、不弱化断言；测试本身有错：停下报告，不自己改。
2. 只改白名单内文件，名称与 Issue 契约一致。不新增依赖。
3. 不吞异常，不伪造结果，不把失败当成功；拿不准安全时默认拒绝。秘密不进日志、提交、PR。

## 停下来问（= X2）
- 要新依赖，或白名单外的文件。
- 业务代码加测试增删超过行数阈值（不含锁文件、自动生成文件、STATUS、docs）；快车道超 20 行。阈值以项目根 `AGENTS.md` 行数节为准，未定义时按 Solo-Flow `WORKFLOW.md` 第 2 节；本文件不写具体数字。估算和实际 diff 都算，只认该阈值，Issue 卡面不另设上限（Human 2026-11-09 批准）。
- 要新增 Issue 里没有的行为规则。
- 发现已确认的范围或验收标准需要调整，或发现已确认需求遗漏，按 WORKFLOW §3 的相应条款处理。
- 分支与 main 冲突。
- 测试意外调用真实服务，或有越权、数据损坏风险：立即停手，保留现场和日志。

## 提 PR 与打回
每张卡都做本地自测。远端 PR 绑定同 SHA 正式 CI，本地通道证据及授权按 WORKFLOW §6。派卡前逐项判断 CI 对各验收点的覆盖；重要且未覆盖的运行、页面、接口或交互行为必须在原卡安排啊bob独立验收及标准；无需介入时在原卡写明覆盖或免验依据。漏写不视为免验，无需另出报告。仅当原卡要求独立运行验收时才叫啊bob；仅 `qa` 标签卡另叫 QA 做同 SHA diff 静态审查。啊bob与 QA 各自读取原卡、验收标准和准确候选 SHA，并各签结论；实现会话不得代签。Codex 负责调度、回修和汇总；所需会话或浏览器能力缺失时，对应验收项标 BLOCKED，其余安全检查继续。两者都需要时分别出结论；四种组合按 Issue 选用，任何角色不得替代另一角色或 CI。QA不跑测试、不写或运行独立用例。持久化/鉴权/分页及其他高风险卡的 `qa` 规则不变。负例需求由实现者或啊bob承接。
- 按 PR 模板填。测试结果以 Actions 为准，不写"已通过"，不自称 QA 通过。
- 打回：Actions 失败直接修；QA FAIL 先补会失败的测试再修。只修已证实的问题，修完在 PR 里说明改了哪些文件。
- 同一张卡第 3 次回修之前停下，报告"建议回大脑重新三问"。

## 留痕
X1、X2、每次回修按 WORKFLOW §3、§5–6 留痕，写时间、原因、当前状态。X1 增记影响范围与可继续的检查，复盘缺停线证据记 UNKNOWN。
同PR同类辅助脚本错误最多两轮，第二轮仍未解除则按已有证据出结论或报Human，不进入第三轮；不碰产品代码、断言、预期与权限的仓外纠正只留一行。候选验收脚本见 Solo-Flow `docs/acceptance-automation.md`。产品回修、安全和白名单边界不变。
